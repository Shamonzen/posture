fail LNX-FW-001 ufw is active and denies incoming traffic by default

With no host firewall, every service that listens on the network (a debug port, a database bound to 0.0.0.0) is reachable by anyone who can route to the host. CIS 4.2.7 covers the default deny policy.

CIS
CIS Ubuntu Linux 24.04 LTS Benchmark v1.0.0, control 4.2.3
ATT&CK
T1190 T1021

Evidence

{
  "fact": "ufw.active",
  "value": false
}
{
  "fact": "ufw.default_incoming",
  "value": null
}

Remediation

Allow SSH first so you don't lock yourself out, then enable ufw with a default deny.

sudo ufw allow OpenSSH
sudo ufw default deny incoming
sudo ufw --force enable
fail LNX-SSH-001 SSH root login is disabled

root exists on every Linux host, so it is the first account password guessers try, and logging in as root directly leaves no trail of which person used it. Admins should log in as themselves and escalate with sudo.

fail LNX-SSH-003 SSH password authentication is disabled

Passwords can be guessed, sprayed or reused from other breaches; SSH keys (or certificates) can't. Not a CIS Level 1 control, but the single most effective SSH hardening step for a host reachable from untrusted networks.

ATT&CK
T1110.001 T1110.003 T1110.004

Evidence

{
  "fact": "ssh.passwordauthentication",
  "value": "yes"
}

Remediation

Make sure every admin has a working key first, then set `PasswordAuthentication no` and reload sshd.

echo 'PasswordAuthentication no' | sudo tee -a /etc/ssh/sshd_config.d/00-posture.conf
sudo sshd -t && { sudo systemctl reload ssh || sudo systemctl reload sshd; }

  • https://man.openbsd.org/sshd_config#PasswordAuthentication
fail LNX-SSH-005 SSH offers no weak ciphers

CBC-mode, 3DES, RC4 (arcfour), Blowfish and CAST ciphers have known weaknesses; a man-in-the-middle can downgrade a connection to whatever the server still accepts.

CIS
CIS Ubuntu Linux 24.04 LTS Benchmark v1.0.0, control 5.1.6
CIS Red Hat Enterprise Linux 9 Benchmark v2.0.0, control 5.1.4
ATT&CK
T1557 T1040

Evidence

{
  "fact": "ssh.ciphers",
  "value": [
    "aes128-cbc",
    "aes256-cbc"
  ]
}

Remediation

Allow only AEAD and CTR ciphers. On Rocky, prefer the system crypto policy (`update-crypto-policies --set DEFAULT`).

echo 'Ciphers aes256-gcm@openssh.com,aes128-gcm@openssh.com,aes256-ctr,aes192-ctr,aes128-ctr' | sudo tee -a /etc/ssh/sshd_config.d/00-posture.conf
sudo sshd -t && { sudo systemctl reload ssh || sudo systemctl reload sshd; }
fail LNX-SSH-006 SSH offers no weak MACs

MD5, RIPEMD-160, SHA-1 and truncated (-96, 64-bit) MACs weaken the integrity protection of the session, which is what stops a man-in-the-middle from altering traffic.

CIS
CIS Ubuntu Linux 24.04 LTS Benchmark v1.0.0, control 5.1.15
CIS Red Hat Enterprise Linux 9 Benchmark v2.0.0, control 5.1.6
ATT&CK
T1557

Evidence

{
  "fact": "ssh.macs",
  "value": [
    "umac-64-etm@openssh.com",
    "hmac-sha1-etm@openssh.com",
    "umac-64@openssh.com",
    "hmac-sha1"
  ]
}

Remediation

Allow only SHA-2 and umac-128 MACs, preferably the encrypt-then-MAC (-etm) ones.

echo 'MACs hmac-sha2-512-etm@openssh.com,hmac-sha2-256-etm@openssh.com,umac-128-etm@openssh.com,hmac-sha2-512,hmac-sha2-256' | sudo tee -a /etc/ssh/sshd_config.d/00-posture.conf
sudo sshd -t && { sudo systemctl reload ssh || sudo systemctl reload sshd; }
fail LNX-SSH-007 SSH offers no weak key exchange algorithms

1024-bit Diffie-Hellman groups and SHA-1 based key exchange are within reach of well-funded attackers and let a man-in-the-middle negotiate down to them.

CIS
CIS Ubuntu Linux 24.04 LTS Benchmark v1.0.0, control 5.1.12
CIS Red Hat Enterprise Linux 9 Benchmark v2.0.0, control 5.1.5

T1557 T1040

sudo sshd -t && { sudo systemctl reload ssh || sudo systemctl reload sshd; }

fail LNX-UPD-003 Security updates are installed automatically

Manual patching slips. Automatic security updates close the window between a fix being published and it being exploited, without waiting for someone to remember.

ATT&CK
T1068 T1190

Evidence

{
  "fact": "updates.automatic",
  "value": false
}

Remediation

Ubuntu: install and enable unattended-upgrades. Rocky: install dnf-automatic with `apply_updates = yes` and enable dnf-automatic.timer.

if command -v apt-get >/dev/null; then
  sudo apt-get install -y unattended-upgrades && echo 'APT::Periodic::Unattended-Upgrade "1";' | sudo tee /etc/apt/apt.conf.d/20auto-upgrades
else
  sudo dnf install -y dnf-automatic && sudo systemctl enable --now dnf-automatic-install.timer
fi
  • https://documentation.ubuntu.com/server/how-to/software/automatic-updates/
  • https://dnf.readthedocs.io/en/latest/automatic.html

fail LNX-LOG-003 journald keeps logs across reboots

With volatile storage the journal lives in RAM: a reboot (or a crash an attacker causes) erases the evidence.

CIS
CIS Ubuntu Linux 24.04 LTS Benchmark v1.0.0, control 6.1.2.4
CIS Red Hat Enterprise Linux 9 Benchmark v2.0.0, control 6.2.2.4
ATT&CK
T1070.002

Evidence

{
  "fact": "journald.persistent",
  "value": false
}

Remediation

sudo mkdir -p /etc/systemd/journald.conf.d
